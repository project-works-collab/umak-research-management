## 2. Phase 1: Supabase Database Provisioning & Security Setup

### 2.1 Project Creation & Password Best Practices
1. Sign up/Log in to [Supabase](https://supabase.com) (free tier, no credit card required).
2. Create project:
   - **Name:** `umak-crm-db`
   - **Region:** `Southeast Asia (Singapore)` (`ap-southeast-1`) for lowest latency to the Philippines.
   - **Database Password:** 
     > [!CRITICAL]
     > Use a strict **24+ character alphanumeric password** (letters and digits only, e.g. generated via `node -e "console.log(crypto.randomBytes(16).toString('hex'))"`). **Avoid special characters** (`@`, `#`, `?`, `/`, `%`) because they break URL parsing inside PostgreSQL connection strings, triggering `28P01: password authentication failed`.

---

### 2.2 Step 1: Create the `crm_app` Role First
In PostgreSQL, `GRANT` statements in the schema will fail with `ERROR: 42704: role "crm_app" does not exist` if the role is not created beforehand.

In the Supabase **SQL Editor**, run:
```sql
-- Create non-owner runtime application role
-- Replace YOUR_SECURE_APP_DB_PASSWORD with an alphanumeric password (16+ chars)
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'crm_app') THEN
    CREATE ROLE crm_app LOGIN PASSWORD 'YOUR_SECURE_APP_DB_PASSWORD' NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION;
  END IF;
END
$$;
```

### 2.3 Step 2: Run Schema Initialization (`db/schema.sql`)
In the Supabase **SQL Editor**, execute the full `db/schema.sql`:
```sql
CREATE TABLE IF NOT EXISTS users (
 id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
 email text UNIQUE NOT NULL,
 password_hash text NOT NULL,
 role text NOT NULL CHECK (role IN ('student','staff'))
);
CREATE TABLE IF NOT EXISTS sessions (
 token_hash text PRIMARY KEY, user_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
 expires_at timestamptz NOT NULL
);
CREATE TABLE IF NOT EXISTS research_records (
 id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
 author_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
 title text NOT NULL CHECK (length(title) BETWEEN 1 AND 200),
 abstract text NOT NULL DEFAULT '',
 status text NOT NULL CHECK (status IN ('Draft','Approved'))
);
CREATE TABLE IF NOT EXISTS consents (
 id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 user_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
 policy_version text NOT NULL, choices jsonb NOT NULL,
 recorded_at timestamptz NOT NULL DEFAULT clock_timestamp()
);
CREATE TABLE IF NOT EXISTS deletion_requests (
 id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 user_id integer REFERENCES users ON DELETE SET NULL,
 status text NOT NULL DEFAULT 'pending' CHECK(status IN ('pending','completed')),
 requested_at timestamptz NOT NULL DEFAULT clock_timestamp(), completed_at timestamptz
);
CREATE UNIQUE INDEX IF NOT EXISTS one_pending_deletion ON deletion_requests(user_id) WHERE status='pending';
CREATE TABLE IF NOT EXISTS audit_logs (
 id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 actor_id integer REFERENCES users ON DELETE SET NULL,
 action text NOT NULL, recorded_at timestamptz NOT NULL DEFAULT clock_timestamp()
);

REVOKE ALL ON SCHEMA public FROM PUBLIC;
REVOKE ALL ON ALL TABLES IN SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public TO crm_app;
GRANT SELECT ON users TO crm_app;
GRANT UPDATE(email) ON users TO crm_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON sessions TO crm_app;
GRANT SELECT, INSERT ON consents TO crm_app;
GRANT SELECT, INSERT, UPDATE ON deletion_requests TO crm_app;
GRANT SELECT, INSERT ON research_records TO crm_app;
GRANT UPDATE(title,abstract) ON research_records TO crm_app;
GRANT SELECT, INSERT ON audit_logs TO crm_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO crm_app;
```

### 2.4 Step 3: Run Stored Procedures, Functions & Migrations
The backend relies on custom stored procedures (e.g. `crm_login_user`, `crm_reserve_login`, `crm_finish_login`, `crm_session_user`) created in `scripts/migrations.js`.

After running the database migration scripts, grant the `crm_app` role permission to execute all `crm_%` routines:
```sql
-- Grant EXECUTE privileges to crm_app on all crm functions
DO $$
DECLARE
  func RECORD;
BEGIN
  FOR func IN
    SELECT routine_name, specific_schema
    FROM information_schema.routines
    WHERE specific_schema = 'public'
      AND routine_name LIKE 'crm_%'
      AND routine_type = 'FUNCTION'
  LOOP
    EXECUTE format('GRANT EXECUTE ON FUNCTION public.%I TO crm_app', func.routine_name);
  END LOOP;
END
$$;

-- Global fallback grant for routines in schema public
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO crm_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT EXECUTE ON FUNCTIONS TO crm_app;
```

### 2.5 Step 4: Configure Row-Level Security (RLS) on Internal Tables
> [!WARNING]
> Supabase automatically activates Row-Level Security (RLS) on newly created tables.
> If RLS is enabled on internal tables without an explicit policy, `INSERT INTO sessions` and `INSERT INTO audit_logs` will fail with **Error `42501` (permission denied for table sessions)** during `/api/v1/auth/login`.

Disable RLS on internal tables whose access is strictly governed by API business logic:
```sql
ALTER TABLE public.sessions DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.audit_logs DISABLE ROW LEVEL SECURITY;
```
*(Leave RLS enabled on `research_records`, `consents`, and user-facing tables where tenant isolation is enforced).*

### 2.7 Step 6: Obtain Pooled Connection String
1. In the Supabase top header, click **Connect**.
2. Select **Transaction pooler** (Port `6543`, Mode `Transaction`).
   > [!NOTE]
   > Do not use port `5432` (session pooler) as its tenant host prefix can trigger `ENOTFOUND tenant/user not found`.
3. Format the URI with the `crm_app` user:
   ```text
   postgresql://crm_app:[YOUR_APP_PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres?sslmode=require
   ```

## 3. Phase 2: Application Code Adjustments

### 3.1 Backend Adjustments (`src/`)
* **`src/server.js`**:
  - Binds to `0.0.0.0` when `NODE_ENV === 'production'`.
  - Enables `app.set('trust proxy', 1)` when running on Render to trust edge TLS termination.
* **`src/security/database-config.js`**:
  - Configured with `ALLOW_UNVERIFIED_DB_TLS=yes` fallback support: enables `{ rejectUnauthorized: false }` for cloud-managed PostgreSQL poolers without breaking strict local/CI CA validation.

### 3.2 Android Application Adjustments (`android/app`)
* **`CrmApi.java`**:
  - Connect & read timeouts increased to **60,000ms (60s)**:
    ```java
    connection.setConnectTimeout(60000);
    connection.setReadTimeout(60000);
    ```
    This eliminates `SocketTimeoutException` when Render free-tier instances wake from sleep.
* **`app/build.gradle`**:
  - `buildConfig true` enabled in `buildFeatures`.
  - `DEFAULT_SERVER_URL` configured with the verified production URL:
    ```groovy
    buildConfigField "String", "DEFAULT_SERVER_URL", "\"https://umak-crm-api.onrender.com\""
    ```
* **`MainActivity.java`**:
  - Auto-initializes persistent server preference to `BuildConfig.DEFAULT_SERVER_URL` on fresh installs.

## 6. Troubleshooting & Common Error Reference

| Error Code / Symptom | Root Cause | Proven Fix |
| :--- | :--- | :--- |
| `ENOTFOUND tenant/user not found` | Attempted connection to session pooler (5432) with mismatched prefix. | Use the transaction pooler on **Port 6543** (`...pooler.supabase.com:6543/postgres`). |
| `28P01: password authentication failed` | Special characters (`@`, `#`, `?`, etc.) in database password broke connection URL parser. | Reset Supabase database password to a strict alphanumeric 24-character string. |
| `42501: permission denied to alter role` | Attempted `ALTER ROLE postgres` directly in Supabase SQL editor. | Bypassed; Supabase reserves `postgres` alterations for `supabase_admin`. Seed users directly in SQL editor. |
| `500 Internal Server Error (42501 on functions)` | `crm_app` role lacked `EXECUTE` privileges on `crm_%` functions. | Run `GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO crm_app;`. |
| `500 Internal Server Error (42501 on sessions)` | Supabase auto-enabled RLS on `sessions` and `audit_logs` without policies for `crm_app`. | Run `ALTER TABLE public.sessions DISABLE ROW LEVEL SECURITY; ALTER TABLE public.audit_logs DISABLE ROW LEVEL SECURITY;`. |
| `404 Route Not Found on /api/v1/research` | Endpoint `/api/v1/research` does not exist as a collection GET. | Use specific routes: `/api/v1/research/1` or `/api/v1/research/search`. |
| `401 Unauthorized` | Bearer token expired (exceeded 900s / 15 mins) or invalid. | Re-authenticate via `/api/v1/auth/login` to obtain a fresh token. |
| `429 Too Many Requests` | More than 5 failed login attempts in 15 minutes triggered rate limiting. | Wait 15 minutes for the rate bucket to refill, or clear records in `rate_buckets`. |
| `403 Forbidden on Login` | User account has `active = false`. | Run `UPDATE users SET active = true WHERE email = 'student1@example.test';`. |
| `SocketTimeoutException` on Android | Render free instance spinning up from sleep (~30-50s cold start). | Ensure `CrmApi.java` timeouts are set to `60000` (60s). Optionally set up an [UptimeRobot](https://uptimerobot.com) ping every 10 mins. |
