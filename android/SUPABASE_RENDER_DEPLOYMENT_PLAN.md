# Cloud Deployment Plan: Supabase (Database) + Render (Backend)

This document provides the complete, end-to-end plan to deploy the **UMak Center for Research Management (CRM)** backend to **Render** and database to **Supabase**, connecting seamlessly to the **Android Application** (`:app` and `:core`).

---

## Architecture Overview

```
                      ┌────────────────────────────────────────┐
                      │          Android Client (App)          │
                      │  • CrmApi.java (HTTPS Client)          │
                      │  • SessionVault (Keystore AES-256-GCM) │
                      │  • PublicSync.java (Room SQLite Cache) │
                      └──────────────────┬─────────────────────┘
                                         │
                                         │ HTTPS /api/v1/...
                                         ▼
                      ┌────────────────────────────────────────┐
                      │         Render.com (Web Service)       │

                      │  • IAS Security Controls & Middleware  │
                      │  • Listens on PORT (0.0.0.0)           │
                      └──────────────────┬─────────────────────┘
                                         │
                                         │ PostgreSQL SSL (Port 6543)
                                         ▼
                      ┌────────────────────────────────────────┐
                      │       Supabase (PostgreSQL Cloud)      │

                      │  • crm_app non-owner role              │
                      │  • Transaction Pooler (Supavisor)      │
                      └────────────────────────────────────────┘
```

## Phase 1: Supabase Database Provisioning

### 1.1 Create Supabase Project
1. Log in to [Supabase](https://supabase.com) (free account via GitHub; no credit card required).
2. Click **New Project**:
   - **Name:** `umak-crm-db`
   - **Database Password:** Generate a secure, 24+ character password (save this securely).
   - **Region:** `Southeast Asia (Singapore)` (`ap-southeast-1`) for lowest latency to the Philippines.
3. Wait ~2 minutes for the database instance to initialize.

---

### 1.2 Create the `crm_app` Role First
> [!IMPORTANT]
> In PostgreSQL, you **must create the role `crm_app` before running `schema.sql`**, because the bottom of `schema.sql` contains `GRANT ... TO crm_app;` statements. If `crm_app` does not exist yet, PostgreSQL throws `ERROR: 42704: role "crm_app" does not exist`.

1. In the Supabase Dashboard, click **SQL Editor** on the left menu.
2. Click **New query** and paste the following snippet:
   ```sql
   -- Create the non-owner crm_app role
   -- Replace YOUR_SECURE_APP_DB_PASSWORD with a strong password (16+ alphanumeric chars)
   DO $$
   BEGIN
     IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'crm_app') THEN
       CREATE ROLE crm_app LOGIN PASSWORD 'YOUR_SECURE_APP_DB_PASSWORD' NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION;
     END IF;
   END
   $$;
   ```
3. Click **Run** (or `Ctrl + Enter`). You should see: `Success. No rows returned`.

---

### 1.3 Run Schema Initialization (`db/schema.sql`)
Now that `crm_app` exists, you can execute the full schema:

1. In the Supabase **SQL Editor**, click **New query**.
2. Paste the full `db/schema.sql` content:
   ```sql
   CREATE TABLE IF NOT EXISTS users (
    id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email text UNIQUE NOT NULL,
    password_hash text NOT NULL,
    role text NOT NULL CHECK (role IN ('student','staff'))
   );
   CREATE TABLE IF NOT EXISTS sessions (
    token_hash text PRIMARY KEY, user_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
    expires_at timestamptz NOT NULL
   );
   CREATE TABLE IF NOT EXISTS research_records (
    id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    author_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
    title text NOT NULL CHECK (length(title) BETWEEN 1 AND 200),
    abstract text NOT NULL DEFAULT '',
    status text NOT NULL CHECK (status IN ('Draft','Approved'))
   );
   CREATE TABLE IF NOT EXISTS consents (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id integer NOT NULL REFERENCES users ON DELETE CASCADE,
    policy_version text NOT NULL, choices jsonb NOT NULL,
    recorded_at timestamptz NOT NULL DEFAULT clock_timestamp()
   );
   CREATE TABLE IF NOT EXISTS deletion_requests (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id integer REFERENCES users ON DELETE SET NULL,
    status text NOT NULL DEFAULT 'pending' CHECK(status IN ('pending','completed')),
    requested_at timestamptz NOT NULL DEFAULT clock_timestamp(), completed_at timestamptz
   );
   CREATE UNIQUE INDEX IF NOT EXISTS one_pending_deletion ON deletion_requests(user_id) WHERE status='pending';
   CREATE TABLE IF NOT EXISTS audit_logs (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    actor_id integer REFERENCES users ON DELETE SET NULL,
    action text NOT NULL, recorded_at timestamptz NOT NULL DEFAULT clock_timestamp()
   );
   REVOKE ALL ON SCHEMA public FROM PUBLIC;
   REVOKE ALL ON ALL TABLES IN SCHEMA public FROM PUBLIC;
   GRANT USAGE ON SCHEMA public TO crm_app;
   GRANT SELECT ON users TO crm_app;
   GRANT UPDATE(email) ON users TO crm_app;
   GRANT SELECT, INSERT, UPDATE, DELETE ON sessions TO crm_app;
   GRANT SELECT,INSERT ON consents TO crm_app;
   GRANT SELECT,INSERT,UPDATE ON deletion_requests TO crm_app;
   GRANT SELECT, INSERT ON research_records TO crm_app;
   GRANT UPDATE(title,abstract) ON research_records TO crm_app;
   GRANT SELECT, INSERT ON audit_logs TO crm_app;
   GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO crm_app;
   ```
3. Click **Run**.
4. Check the **Table Editor** on the left menu to verify that `users`, `sessions`, `research_records`, `consents`, `deletion_requests`, and `audit_logs` are all visible.

### 1.5 Obtain Connection URI (New Supabase UI)
> [!NOTE]
> In the updated Supabase dashboard, connection strings are no longer located under Project Settings. Supabase moved database configuration to the top header and the left sidebar **Database** tab.

Choose either of the two ways to get your connection URI:

#### Method A: The "Connect" Button (Fastest)
1. In the **top navigation bar / header** (near your project name and branch indicator), click the **`Connect`** button.
2. A modal will pop up.
3. Select **ORMs** or **Transaction pooler**:
   - Tab: **Connection String** -> **URI**
   - Mode: **Transaction** (Port `6543`)
4. Copy the connection string.

#### Method B: Left Sidebar "Database"
1. In the left sidebar, click the **Database** icon (stacked cylinder icon).
2. Click **Configuration** (or **Connection Pooling**).
3. Under **Connection Pooler (Supavisor)**, copy the URI with port `6543`.

#### Format the Final URI for Render:
Replace the user with `crm_app` and password with your `YOUR_SECURE_APP_DB_PASSWORD`:
```text
postgresql://crm_app:[YOUR_APP_PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres?sslmode=require
```
Save this URI—you will paste it as `DATABASE_URL` in Render.

## Phase 2: Application Code Adjustments for Cloud Deployment

### 2.1 Backend Adjustments (`src/`)
1. **Server Host Binding (`src/server.js`)**:
   - Currently, `server.js` binds to `process.env.HOST || '127.0.0.1'`.
   - In cloud container environments (Render/Docker), it **must** listen on `0.0.0.0`.
   - Update: `const host = process.env.HOST || (process.env.NODE_ENV === 'production' ? '0.0.0.0' : '127.0.0.1');`
2. **Reverse Proxy SSL Termination**:
   - Render terminates SSL at the edge load balancer and forwards plain HTTP internally with `x-forwarded-proto: https`.
   - Ensure `process.env.TLS_CERT_FILE` is optional on Render, trusting the edge proxy:
     `app.set('trust proxy', 1);`
3. **Database SSL CA Verification (`src/security/database-config.js`)**:
   - Preserves strict CA verification in production while allowing cloud database SSL when `ALLOW_UNVERIFIED_DB_TLS=yes` is set on Render.

### 2.2 Android Application Adjustments (`android/app`)
1. **Connection Timeout Increase (`CrmApi.java`)**:
   - Render Free Tier instances spin down after 15 minutes of inactivity and take ~30–50 seconds to wake up upon receiving a request.
   - Current setting in `CrmApi.java`:
     ```java
     connection.setConnectTimeout(10000); // 10 seconds -> will fail on cold start
     connection.setReadTimeout(15000);
     ```
   - Update to:
     ```java
     connection.setConnectTimeout(60000); // 60 seconds for cloud cold-start resilience
     connection.setReadTimeout(60000);
     ```
2. **Default Production Server URL (`app/build.gradle` & `MainActivity.java`)**:
   - Currently, `MainActivity` defaults to an empty server preference and prompts the user with an input dialog.
   - Configure `buildConfigField "String", "DEFAULT_SERVER_URL", "\"https://your-crm-api.onrender.com\""` in `app/build.gradle`.
   - If `preferences.getString("server", "")` is empty, auto-populate with `BuildConfig.DEFAULT_SERVER_URL`.

## Phase 3: Render Backend Deployment

### 3.1 Push Repository to GitHub
1. Commit the code adjustments to your GitHub repository (Render deploys directly from GitHub).

### 3.2 Create Web Service on Render
1. Sign up/Log in to [Render](https://render.com) using your GitHub account (no credit card required).
2. Click **New +** → **Web Service**.
3. Select your `umak-research-management` repository.
4. Set configurations:
   - **Name:** `umak-crm-api`
   - **Region:** `Singapore` (matches Supabase database region)
   - **Branch:** `main` (or your active branch)
   - **Runtime:** `Node`
   - **Build Command:** `npm ci --ignore-scripts`
   - **Start Command:** `npm start`
   - **Instance Type:** `Free` (512 MB RAM)

### 3.3 Set Environment Variables on Render
Add the following in the **Environment** tab:

| Environment Variable | Value / Description |
| :--- | :--- |
| `NODE_ENV` | `production` |
| `HOST` | `0.0.0.0` |
| `PORT` | `10000` (Render's default) |
| `DATABASE_URL` | Supabase pooled connection URI (`postgresql://crm_app:...@...pooler.supabase.com:6543/postgres?sslmode=require`) |
| `ALLOW_UNVERIFIED_DB_TLS` | `yes` (allows cloud provider managed TLS without local CA certificate) |
| `JWT_SIGNING_KEY` | 64-character hex string (generate locally: `openssl rand -hex 32`) |
| `DEMO_PASSWORD` | Test accounts password |
| `ALLOW_SYNTHETIC_SETUP` | `yes` |

Click **Create Web Service**. Render will build and deploy the container and assign a public HTTPS URL (e.g., `https://umak-crm-api.onrender.com`).

## Phase 4: Verification & Integration Testing

### 4.1 Verify Backend & Database Health
1. Test API reachability:
   ```bash
   curl -i https://umak-crm-api.onrender.com/api/v1/public/content
   ```
   *Expected response:* HTTP 200 with JSON payload listing public catalog items.
2. Test Authentication endpoint:
   ```bash
   curl -i -X POST https://umak-crm-api.onrender.com/api/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"student1@example.test","password":"YOUR_DEMO_PASSWORD"}'
   ```
   *Expected response:* HTTP 200 containing `access_token` and `expires_in`.

### 4.2 Verify Android Client Connectivity
1. Build and install the app on an Android device or emulator:
   ```bash
   cd android
   ./gradlew :app:installDebug
   ```
2. Launch the app:
   - Go to **Need Help? → CRM server settings**.
   - Ensure the server address is set to: `https://umak-crm-api.onrender.com`.
3. Test guest / public sync:
   - Tap **Continue as Guest**. Verify public resources and templates load from Supabase through the Render API.
   - Verify `PublicSync` inserts data into the local Room database (`crm-public.db`).
4. Test student sign-in:
   - Sign in as `student1@example.test`.
   - Verify Keystore token encryption (`SessionVault`), researcher studies screen, and consultation queue.
5. Test staff sign-in:
   - Sign in as `staff@example.test`.
   - Verify 5-tab staff workspace loads review queue and research records.

### 4.3 Handle Free-Tier Cold Starts & Keep-Alive
- To prevent Render from falling asleep during class demonstrations or testing, configure a free monitor at [UptimeRobot](https://uptimerobot.com) to ping `https://umak-crm-api.onrender.com/api/v1/public/content` every 10 minutes.
- This also prevents Supabase's 7-day inactivity pause.
