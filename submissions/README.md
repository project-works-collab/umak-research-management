## Regenerate

Requirements: Node 24; Python 3.12+ with `pip install -r submissions/requirements.txt`; Arial font files (or supply their directory through `REPORT_FONT_DIR`). Deck build additionally uses the Codex bundled `@oai/artifact-tool` 2.8.59 and installed Presentations skill validation utilities. This authoring runtime is not an application dependency and is not installed by `npm ci`.

Set `RUNTIME_NODE_MODULES`, `RUNTIME_PYTHON`, and `PRESENTATIONS_SKILL` to your installed runtime/skill paths, obtained from Codex workspace dependencies. Use a fresh staging directory for every run because the deck finalizer preserves prior outputs. From repository root:

```bash
mkdir -p .private
BUILD_DIR=$(mktemp -d "$PWD/.private/submissions.XXXXXX")
cp submissions/sources/*Report.md submissions/sources/slides.json "$BUILD_DIR/"
cp -R submissions/figures "$BUILD_DIR/figures"
node submissions/build-slides.mjs "$BUILD_DIR"
"$RUNTIME_PYTHON" submissions/build_reports.py --root "$BUILD_DIR"
```

The candidate PPTX, page images and validation receipts stay under `build/`; final PPTX/PDF files are under `output/`. Both reports append the 14 slide images generated by that same deck build. Inspect every rendered report/slide page before replacing submitted files. Use Poppler `pdftoppm -r 120 -png` for PDF inspection. The report builder reads figures from the staging `figures/` directory and fails on missing images.

After an intentional diagram/model change, reopen the JSON in Threat Dragon, verify both levels and export the rendered SVG again; update its portable PNG and source together. Re-render SVG with an SVG-capable renderer such as Sharp. Do not substitute a schema check for a UI rendering check.
